The contracts

One core contract owns all money and ordering. Three small pieces plug into it by address, so v1 can ship them as a single key each and v2 can replace them with real contracts without touching escrow.

Bazaar

core · escrow, commitments, attestations, settlement

Everything with a balance or an ordering lives here. It never calls out to anything except sending ETH. It trusts exactly two addresses: whoever verifierSet says can attest, and arbiter.

enum BountyStatus { OPEN, VOIDED, CLOSED } enum Outcome { NONE, PASS, PASS_NO_SLOT, FAIL, VOID, RECLAIMED } enum Dispute { NONE, OPEN, RESOLVED } struct Invariant { uint96 reward; uint8 slots; uint8 slotsUsed; uint32 cursor; uint32 commitCount; } struct Bounty { address buyer; bytes32 manifestHash; bytes32 controlHash; uint64 expiry; uint96 minBond; uint8 k; uint16 controlTierBps; uint128 escrow; uint32 pending; BountyStatus status; Invariant[] inv; } struct Commit { uint64 bountyId; uint8 inv; uint32 seq; address seller; bytes32 commitment; uint96 bond; uint64 committedAt; Outcome outcome; uint8 hits; bool breaksControl; bool slotHeld; bytes32 contentHash; bytes32 traceHash; uint64 attestedAt; Dispute dispute; address disputer; uint96 disputeBond; bool finalized; } config: verifierSet, arbiter, treasury, attestTimeout, disputeWindow, disputeBond, cancelGrace
postBounty(manifestHash, controlHash, rewards[], slots[], expiry, minBond, k, controlTierBps) payableanyone · msg.sender becomes buyer
Requires msg.value == Σ rewards[i]·slots[i] and expiry > now. Locks escrow, status OPEN. If a BudgetVault calls this, the vault is the buyer and receives refunds.
commit(bountyId, inv, commitment) payableseller
Requires OPEN, now < expiry, msg.value ≥ minBond. Assigns seq = inv.commitCount++, pending++. The commitment is keccak(contentHash ‖ salt) where contentHash = keccak(transcript).
attest(commitId, outcome, hits, breaksControl, contentHash, salt, traceHash)verifierSet.canAttest(msg.sender)
Requires outcome == NONE and seq == inv.cursor (FIFO). For PASS, requires keccak(contentHash ‖ salt) == commitment; takes a slot if one is free, otherwise the contract stores PASS_NO_SLOT. FAIL and VOID need no commitment proof. Sets attestedAt, cursor++. No ETH moves here.
dispute(commitId) payablebuyer on PASS · seller on FAIL
Requires now < attestedAt + disputeWindow, dispute == NONE, msg.value ≥ disputeBond. Freezes finalize until resolved.
resolve(commitId, final)arbiter
Requires dispute OPEN; final ∈ {PASS, FAIL}. PASS→FAIL releases the slot; FAIL→PASS takes one if free (else PASS_NO_SLOT). Dispute bond goes to the disputer if the outcome changed, to the counterparty if upheld. Marks RESOLVED.
finalize(commitId)anyone
Requires an outcome, not finalized, and either the window elapsed with no dispute or dispute RESOLVED. PASS: paid = reward · (breaksControl ? controlTierBps/10000 : 1), escrow −= paid, seller gets paid + bond. PASS_NO_SLOT / VOID: bond back to seller. FAIL: bond to treasury. pending−−. This is the only function that pays a seller.
reclaimBond(commitId)seller
Requires outcome == NONE, seq == inv.cursor, and either now > committedAt + attestTimeout or bounty VOIDED. Marks RECLAIMED, cursor++, pending−−, bond back. In-order reclaim is what stops a dead verifier from wedging later commits.
voidBounty(bountyId)verifierSet
Model gone or manifest unrunnable. Status VOIDED: no new commits, unattested commits reclaim immediately, already-attested ones settle normally, expire allowed at once.
cancel(bountyId)buyer
Soft cancel: expiry = min(expiry, now + cancelGrace). Never an instant close, so a seller mid-attack keeps a window to commit.
expire(bountyId)anyone
Requires now ≥ expiry or VOIDED, and pending == 0. Returns remaining escrow to buyer, status CLOSED.
events: BountyPosted · Committed · Attested · Disputed · Resolved · Finalized · Reclaimed · BountyVoided · BountyCancelling · BountyExpired

IVerifierSet

who may attest

One view function: canAttest(address) → bool. The core never stores a verifier address of its own.

v1 · SingleVerifierowner can rotate the address
Returns true for exactly one key: the platform's verifier service. Ten lines.
v2 · StakedVerifierSetthreshold m-of-n
Verifiers stake to join; attest grows a signature-bundle variant and the core asks the set for its threshold. Slashing a verifier whose attestation is overturned by the arbiter is where cases 20 and 21 stop being trust assumptions.

Arbiter

who may resolve

A role, not a contract, in v1: resolve checks msg.sender == arbiter. Anything can sit behind that address later.

v1 · platform keysame operator as the verifier
Re-runs the replay and rules. Honest about what this means: seller-vs-verifier disputes are only meaningful once this key is independent.
v2 · JuryArbiterstaked jurors, or a second verifier set
Jurors receive the manifest and transcript, replay, vote; the contract calls resolve with the majority. Dispute bonds fund juror rewards.

BudgetVault

optional · spend policy for an autonomous buyer

A coding agent holding a raw key can post fifty bounties a day. The vault makes the cap a contract rule instead of a CLI setting. Deploy one per buyer; it is the buyer from the Bazaar's point of view.

owner (human) · spenders[] (agent keys) · perBountyCap · epochCap · epochLength spentThisEpoch · epochStart · balance
deposit() payable · withdraw(amount) · setSpender(key, ok) · setCaps(...)owner
The human funds and configures it once.
postBounty(params)spender
Rolls the epoch, requires total ≤ perBountyCap and spent + total ≤ epochCap, then calls bazaar.postBounty{value: total}. Refunds from expire land back in the vault via receive().
dispute(commitId) · cancel(bountyId)spender
Forwarded buyer actions, so the agent can defend and wind down bounties without holding the vault's balance.

Not contracts

deliberately
Reputation
Computed by the indexer from Attested and Finalized events, weighted against wash trading (case 13). An on-chain score would be a target.
Treasury
An address that receives slashed bonds. Never the buyer, so a FAIL is never something the buyer profits from.
Manifest · transcript · trace
Off-chain, referenced by hash. The prompt and the exploit are the two things that must never be public.

Lifecycles

Two state machines. A commit can only be paid from PASS via finalize, and can only leave NONE through the verifier or an in-order reclaim.

Invariants worth a Foundry invariant test

If these hold under random sequences of the calls above, the edge cases hold too.

address(this).balance == Σ escrow + Σ bonds(unfinalized, unreclaimed) + Σ open disputeBondsNo ETH is ever unaccounted for; slashed and paid amounts leave, everything else is owed to someone.
inv.slotsUsed ≤ inv.slotsSlots are taken at attest, released only by a resolve that overturns a PASS.
inv.cursor ≤ inv.commitCount and every commit with seq < cursor has outcome ≠ NONE. FIFO: nothing is skipped, nothing is attested twice.
bounty.pending == count(commits where !finalized ∧ outcome ≠ RECLAIMED)The refund gate is exact.
status == CLOSED ⇒ escrow == 0 ∧ pending == 0Closing is terminal and empty.
Σ paid to seller for commit ≤ inv.rewardTiered payouts never exceed the posted reward; the remainder returns at expire.
